================================================================================
          CLASSSYNC AI - GUIA DE IMPLANTAÇÃO NO GOOGLE CLOUD (GCP)
================================================================================

1. VISÃO GERAL DA ARQUITETURA
--------------------------------------------------------------------------------
O ClassSync AI (FastAPI + SQLAlchemy/SQLite + Frontend SPA) é executado no
Google Cloud Run em modo Serverless utilizando Docker, com persistência do banco
de dados SQLite montado diretamente a partir de um Bucket no Google Cloud Storage.

- Serviço Principal: Google Cloud Run (Execução do container FastAPI)
- Persistência: Google Cloud Storage Bucket montado como Volume (Cloud Storage FUSE)
- Porta do Serviço: 8080 (injetada dinamicamente via variável $PORT)
- Build da Imagem: Google Cloud Build (compilação automática via Dockerfile)


2. PRÉ-REQUISITOS
--------------------------------------------------------------------------------
1. Conta no Google Cloud com faturamento (billing) ativo.
2. Google Cloud SDK (gcloud CLI) instalado ou acesso ao Google Cloud Shell no navegador.
3. Código-fonte do projeto com Dockerfile na raiz.


3. PASSO A PASSO DE IMPLANTAÇÃO
--------------------------------------------------------------------------------

[PASSO 1] Configuração do Projeto GCP e Ativação de APIs
Execute no terminal (PowerShell, Bash ou Cloud Shell):

  # 1. Login na conta Google
  gcloud auth login

  # 2. Definir o ID do projeto GCP
  export PROJECT_ID="meu-projeto-classsync"
  gcloud config set project $PROJECT_ID

  # 3. Habilitar as APIs do Cloud Run, Cloud Build, Artifact Registry e Storage
  gcloud services enable run.googleapis.com \
                         cloudbuild.googleapis.com \
                         artifactregistry.googleapis.com \
                         storage.googleapis.com


[PASSO 2] Configuração da Persistência do Banco de Dados (SQLite)
Como os containers do Cloud Run são efêmeros por padrão, criamos um Bucket no
Cloud Storage para persistir o arquivo "project.db":

  # 1. Definir região e nome do bucket
  export REGION="us-central1"
  export BUCKET_NAME="classsync-db-storage-${PROJECT_ID}"

  # 2. Criar o bucket no Cloud Storage
  gcloud storage buckets create gs://${BUCKET_NAME} \
      --location=${REGION} \
      --uniform-bucket-level-access


[PASSO 3] Build e Deploy Direto no Cloud Run
Execute o comando de deploy a partir da raiz do projeto:

  gcloud run deploy classsync-ai \
      --source . \
      --region ${REGION} \
      --platform managed \
      --allow-unauthenticated \
      --port 8080 \
      --memory 1Gi \
      --cpu 1 \
      --execution-environment gen2 \
      --add-volume name=db-storage,type=cloud-storage,bucket=${BUCKET_NAME} \
      --add-volume-mount volume=db-storage,mount-path=/app/db

O Cloud Build compilará o Dockerfile, criará o container e publicará a aplicação
com HTTPS automático e volume persistente montado em /app/db.


[PASSO 4] Validação e Acesso ao Sistema
Após a conclusão, o gcloud exibirá a URL do serviço (ex: https://classsync-ai-xxxx-uc.a.run.app).

  - Painel Web (SPA): https://<URL-DO-CLOUD-RUN>/
  - Documentação OpenAPI / Swagger: https://<URL-DO-CLOUD-RUN>/docs

  Credenciais padrão do administrador inicial:
    * Usuário: admin@classsync.ai
    * Senha:   admin123


4. BOAS PRÁTICAS PARA AMBIENTE DE PRODUÇÃO
--------------------------------------------------------------------------------
- Gerenciamento de Segredos: Armazene variáveis sensíveis e tokens no Secret Manager
  e injete via flag "--set-secrets" no Cloud Run.
- Migração para Banco Relacional: Para alta concorrência com múltiplos nós simultâneos,
  migre o SQLite para Cloud SQL (PostgreSQL), ajustando apenas a variável de banco
  em src/database.py.
- Domínio Customizado: Associe seu domínio próprio (ex: app.universidade.edu.br)
  diretamente no Cloud Run com certificado SSL gerenciado gratuitamente.
- Controle de Custo: A flag "--min-instances 0" permite que o custo seja zero
  quando não houver requisições ativas.
